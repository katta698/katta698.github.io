The week in one paragraph

132 notes across 46 products, against 245 last week — and for the second consecutive week, no security bulletins at all. The inventory below rolled up nothing, which is its own signal: there was no Container Optimized OS CVE run this week, so the notes are 130 genuinely distinct facts rather than one release repeated. In a week with that little noise, the item worth your time is a hardware deprecation that arrived in two halves, and the second half is stranger than the first.

The GPU retirement, in two stages

Compute Engine published two deprecation notes on the same day, and they are at opposite ends of their lifecycles.

The first is already done. As of September 15, 2026, NVIDIA P100 GPUs have reached end of support and are shut down — you can no longer create, launch, or access Compute Engine instances or other Google Cloud resources that use them. That is a past-tense announcement: if it affected you, it affected you ten days before the note appeared in this week's feed.

The second is the interesting one. NVIDIA T4 and P4 GPUs are deprecated and will reach end of support on August 1, 2027 — eleven months away, which sounds comfortable. But one consequence lands now rather than then: you can no longer purchase or renew 3-year committed use discounts for NVIDIA T4 or P4 GPUs.

That is worth separating out, because a deprecation notice usually reads as a single date you diary and forget. This one has two. The capability ends in August 2027; the economics ended the moment the note was published. Anyone running T4 fleets on expiring commitments is now choosing between on-demand pricing for the remainder or an early migration — and the arithmetic favours migrating sooner than the EOS date implies. Google names the destinations: supported GPU alternatives such as the G2 (NVIDIA L4) or G4 (NVIDIA RTX PRO 6000) machine series.

T4 is the one that will hurt broadly. It has been the default cheap inference GPU on Google Cloud for years, which means it is embedded in a lot of ML serving that nobody has revisited since it was built.

Two more dated deadlines

  • MySQL 5.6 and 5.7 in the Data Studio connector — creating new data sources against those versions stops being possible after 26 February 2027, and existing data sources or reports that use MySQL 5.6 or 5.7 might not properly load data after that date. Note the second half: this is not only a block on new connections, it is a warning that existing reports may stop working.
  • NVIDIA T4 and P4 — 1 August 2027, as above, with the discount consequence already in effect.

Added to last week's four, that is six dated deprecations inside a fortnight, every one of them landing in 2027. The pattern from last week holds: a deprecation note is not a task, it is a date, and the failure mode is reading it now and having nowhere to put it.

Platform, data and the rest

  • Dataplex gained a genuinely useful access-control primitive: data products now support configuring a default IAM role in an access group, and the default role, once configured, is automatically granted on all packaged and supported assets in the data product. Owners can override it per asset, and the assets table now shows each asset's permission state as Applied, Failed or Unsupported. That last part matters more than it reads — a grant that silently failed on one asset is exactly the gap that makes access audits unreliable.
  • Storage Transfer Service added two filters in one day: Amazon S3 source objects can be filtered by storage class, and source objects can be filtered using glob patterns with wildcard characters such as * and ?. Between them those remove a common reason for writing a custom transfer job.
  • BigQuery had a quiet quality week in BigQuery Studio — row numbers stay visible when the results table scrolls horizontally, and the Query results pane now shows a short history of recent runs for a query, including multi-statement queries. Neither is a headline; both are the kind of thing you notice every day.
  • Security Command Center renamed several AI Protection finding categories to clarify that it detects tuned models. Renamed finding categories are a detection-content migration for anyone matching on those names.
  • Apigee X and Apigee hybrid both shipped security fixes, including a patched Java Callout policy issue and CVE fixes in apigee-asm-ingress. No bulletin was raised for either.
  • GKE published its regular (2026-R40) security update, with new versions on updated Container-Optimized OS images.

What I would act on

  1. Inventory your T4 and P4 usage this week, not next year. The EOS date is August 2027 but the committed use discounts stopped being renewable now, so the cost case for migrating is already worse than it was last month.
  2. Confirm nothing of yours was on P100. That deprecation is in the past tense — the shutdown happened on 15 September.
  3. Check Data Studio reports for MySQL 5.6 and 5.7 sources, because the warning covers existing reports failing to load data, not just new connections being blocked.
  4. If you use Dataplex data products, look at the new permission state column. Assets showing Failed are grants you believe you made and do not have.
  5. Grep detection content for the renamed Security Command Center AI Protection categories before the old names disappear from your rules.
