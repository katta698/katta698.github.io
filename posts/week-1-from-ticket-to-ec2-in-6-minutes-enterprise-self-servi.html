Every large enterprise has this problem: a developer needs a VM. They open a ticket. It goes to a queue. Someone reads it three days later, asks clarifying questions, manually clicks through the AWS console, and emails back a hostname. The developer has moved on.

This week I built the automated version of that story. Lab Overview

Someone needs an EC2 instance. What stands between them and having one?

The problem. Usually a ticket, a queue and an engineer who runs the same handful of API calls they ran last week. The work takes minutes; the waiting takes days, and the engineer is the bottleneck by design rather than by accident.

The objective. A ServiceNow catalogue item that produces a real, tagged, governed EC2 instance with no one in the middle, and a ticket that closes itself with the instance details.

The outcome. Ticket to running instance in about six minutes. One thing does not work: the ServiceNow developer instance will not accept the write-back, which is a limitation of the free tier rather than of the pipeline, and the post says so.

Cloud Services and Concepts

ServicePurpose hereWhat it is
Amazon EC2The thing being provisionedVirtual machines you rent by the second. You choose the size and the operating system, and you are responsible for what runs on them.
AWS Step FunctionsRuns provisioning as declared stepsRuns a workflow as an explicit state machine, so each step, its retry behaviour and its failure path are declared rather than buried in code.
AWS LambdaReceives the request and calls the AWS APIsRuns a piece of code on demand with no server to manage. You are billed per request and per millisecond it runs.
Amazon API GatewayThe endpoint ServiceNow posts toA managed front door that accepts HTTP requests and forwards them to a backend.
AWS Systems ManagerReaches the instance without SSHManages instances through an agent already on them, so there is no inbound port to open and no key to distribute.
TerraformDeclares all 74 resourcesInfrastructure as code: you describe the resources you want and Terraform works out what to create, change or destroy to get there.

The idea the whole series starts from is that self-service is not a UI problem. The catalogue item is the easy part; what makes it safe is that the instance arrives already tagged, already governed and already reachable without a key, because the pipeline had no way to produce one that was not.

Security and Cost

Security Patterns Baked In

No SSH keys anywhere. EC2 instances use SSM Session Manager (AmazonSSMManagedInstanceCore). Connect with aws ssm start-session --target i-xxx. No key pair, no port 22, no bastion host.

IMDSv2 enforced. Launch template sets http_tokens = "required". Blocks SSRF attacks from reaching the metadata endpoint.

Private subnets. EC2 lives in private subnets, unreachable from the internet. Only accessible through the ALB.

OIDC for GitHub Actions. No AWS_ACCESS_KEY_ID in GitHub Secrets. GitHub exchanges a JWT for temporary STS credentials scoped to your specific repo.

Secrets in SSM Parameter Store. ServiceNow credentials and GitHub token stored as SecureString (KMS-encrypted). Never in env vars, never in code, never committed to git.

Troubleshooting and Lessons

This is where a post usually jumps to "and then it worked". Four things had to be fixed first, and three of them were a name that did not match another name.

Problem. ServiceNow fired the webhook and API Gateway returned 502.
Root cause. Terraform created the function with STATE_MACHINE_ARN and the handler read STEP_FUNCTION_ARN. The KeyError crashed the function, and a crashed function is a 502 at the gateway.
Resolution. Align the name in the handler with the one Terraform sets.
Lesson. An environment variable is an interface between two files that never see each other. 502 is what that mismatch looks like from outside.

Problem. Every function failed with Runtime.HandlerNotFound.
Root cause. Terraform declared the handler as handler.lambda_handler; all three files defined def handler.
Resolution. Renamed the functions to lambda_handler.
Lesson. The same mismatch as the first bug in a different place. The runtime cannot tell you a function is missing until it is already running.

Problem. The execution failed at CheckValidation: the path $.validation.Payload.valid was not found.
Root cause. The validation step reused the status updater, which returns no valid field, so the Choice state was reading a field that had never existed.
Resolution. Replaced the task with a Pass state for the lab.
Lesson. Reusing a function because it is the right shape is not the same as it returning the right thing.

Problem. The deployment trigger got 404 from the GitHub API.
Root cause. The token was scoped to public_repo and the repository is private, so it was invisible to that token and the failure presented as a missing repository rather than a refused one.
Resolution. A token with repo scope. On Git Bash, set MSYS_NO_PATHCONV=1 when writing the parameter, or the path is rewritten to C:/selfservice-ec2/... before the CLI sees it.
Lesson. A not-found from an API you are authenticated to is worth reading as a scope problem before a missing resource.

Cleanup and Key Takeaways

The waitForTaskToken pattern in Step Functions is underused. Most people either poll (wasteful) or fire-and-forget (lose visibility). The callback pattern gives you synchronous visibility into a long-running async process with zero idle cost.

version = "$Latest" in ASG launch templates is a silent footgun. Terraform doesn't see LT version changes as an ASG change. Always use aws_launch_template.app.latest_version to trigger instance refresh automatically.

IMDSv2 + private subnets + SSM is the modern EC2 security baseline. If any deployment in your org still has a key pair and port 22 open, that's technical debt worth addressing.

Design every external call as best-effort. Your infrastructure pipeline should never be blocked by a downstream ITSM system. Graceful degradation is a feature, not a workaround.
