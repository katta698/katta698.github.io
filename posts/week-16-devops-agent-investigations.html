Lab Overview

Every incident ends with somebody writing a sentence. "The IAM change at 14:02 removed the parameter read, and that is why orders stopped." That sentence is the deliverable — it goes in the postmortem, the next person reads it, and the fix is built on it.

The problem. An investigating agent writes that sentence for you, in about sixteen minutes, at three in the morning. That is genuinely useful, and it is the exact reason to be careful: a fluent wrong sentence and a fluent right one look identical. A metric that is wrong is visibly wrong. A narrative that is wrong reads like an explanation.

The objective. Not "can an agent investigate" — obviously yes. The question is how would I know if it were wrong, answered before an agent's conclusion is allowed to shorten anybody's thinking.

The outcome. The agent was right, twice. I still had to check — and the checking found that I had left the answer key in the room.

"Monitor" is not a setting here, it is the only option. AccountType has exactly one legal value, and no actions-role property exists on either CloudFormation resource. The agent reads and recommends; it cannot act, and that is enforced by the service rather than chosen by me.

Grading, not admiring. The method is to write the ground truth down before asking, then mark the answer against it. Anything recorded afterwards is a reaction to the answer, not a test of it.

Architecture and Workflow

  1. A small scheduled Lambda workload runs normally, reading an SSM parameter on every invocation.
  2. A deliberate break is introduced: the role's ssm:GetParameter is revoked. The workload starts failing.
  3. The ground truth is written down first, in a shell script, before the agent is asked anything.
  4. An investigation is started in the agent space, whose reach is entirely declared in Terraform.
  5. The agent reads CloudTrail, CloudWatch and the resource configuration, and declares what it could not see.
  6. It produces a root cause and a mitigation plan. A human reads the plan and performs the repair.
  7. The answer is marked against the ground truth written in step 3.

Design decisions

A second, decoy investigation. One correct answer proves very little. The decoy run introduced a repair and a re-break, so the agent had to reconstruct a sequence rather than name a single event.

No auto-remediation. An agent that can act on a wrong narrative is a different risk category from one that can only propose it. I originally wrote this up as a design decision; reading the CloudFormation schemas showed it is not one — the service permits nothing else.

Both service roles double-scoped. aws:SourceAccount pins the caller to this account, aws:SourceArn to an agent space ARN in this account and region, against the confused-deputy case.

Security and Cost

Security

The agent reads and recommends; it never acts — enforced by the service, not chosen by me. AccountType accepts only monitor and no actions-role property exists, so the whole IaC path is read-only.

Both service roles double-scoped with aws:SourceAccount and aws:SourceArn, against the confused-deputy case.

The service namespace is aidevops, not devops-agent. Getting it wrong yields a trust policy that looks right and never matches.

AWS managed policies rather than hand-rolled read access. Hand-writing least-privilege across every service an investigator might touch is a losing game.

The standing grant is the thing to remove. An idle agent space costs nothing — verified on every meter — so what persists is not a bill but a role a managed AWS service can assume to read your account.

Troubleshooting and Lessons

I left the answer key in the room

Problem. The first investigation's root cause ended with a sentence I did not expect: "The SSM parameter's own description confirms this was a deliberate break."
Root cause. It did — because I wrote it, in the Terraform, months earlier:

description = "Read on every invocation. Revoking the role's ssm:GetParameter is the deliberate break."

That description is a comment to a human reader and a signpost to anything that can read the AWS API. The agent read it and named the exact mechanism the test was about.
Resolution. Scrub the environment before evaluating. Less was invalidated than it first appears — the description says which permission matters, not who removed it, when or from where, and the causal chain still came from CloudTrail. The decoy run reconstructed a sequence the description could not have contained.
Lesson. Your resource descriptions are inputs to the agent. Scrub them before evaluating; write them well before operating.

The declared gaps matter more than the conclusion

Problem. How do you trust a fluent narrative at all?
Root cause. You cannot, from the narrative. You can from what it admits it could not see.
Resolution. The agent reported being denied lambda:GetFunction and said so.
Lesson. Being told it was denied something is what makes the rest believable. An agent that returns the same confident paragraph whether or not it could see the evidence is the one to worry about.

Read the mitigation plan; do not run it

Problem. One run proposed a repair broader than the permission that had been removed.
Root cause. A plan optimises for "make it work", not for "restore the prior boundary".
Resolution. A human performed the repair, scoped to what was actually revoked.
Lesson. The plan is a proposal from something that cannot act. Keep it that way.

Cleanup and Key Takeaways

Everything this week creates is a Terraform resource, including the agent space and both associations, so nothing is left behind by design. Two things still need confirming:

  • The agent space. Left behind it costs nothing while idle — genuinely nothing, verified on every meter — which is exactly what makes it easy to forget. What persists is not a bill but a standing grant: a role a managed AWS service can assume to read your account. Remove it deliberately.
  • The ServiceNow OAuth endpoint is not managed by Terraform and does not disappear with the stack. Deactivate the Application Registry record, or the credential outlives the lab.

The observed workload tears down with everything else — the S3 bucket carries force_destroy and a seven-day lifecycle rule, so teardown never needs a manual empty.

Key takeaways

  • An agent returns a narrative, and narratives persuade regardless of accuracy. A wrong metric looks wrong; a wrong explanation reads like an explanation. That asymmetry is the whole reason to grade rather than admire.
  • Write the ground truth down before you ask. Anything recorded afterwards is a reaction to the answer, not a test of it.
  • Your resource descriptions are inputs to the agent. I put the answer in an SSM parameter description and it was quoted back to me.
  • The declared gaps matter more than the conclusion. An agent that sounds equally confident with and without the evidence is the one to distrust.
  • Price the thing before you run it. A flat $5.03 per investigation and an undocumented $13.22 one-time charge made this the most expensive week in the series.
